# 정적 사이트 생성 스크립트 계약서

이 문서는 `scripts/build-static-site.ps1`이 입력으로 받아들이는 형식, 입력을 변환하는 규칙, 생성하는 결과, 거부해야 하는 문서, 파일을 안전하게 갱신하는 경계를 정의합니다. **새 일기·사진을 작성하거나 스크립트를 수정할 때 따르는 프로젝트의 기준 규격**입니다.

스크립트 동작과 이 계약이 달라지면 둘 중 하나를 임의로 무시하지 않습니다. 의도한 동작을 정하고 스크립트와 이 문서를 함께 수정한 뒤 기존 콘텐츠로 생성·검사해야 합니다. README는 사용 안내이고, 입력·파싱·출력에 관한 세부 약속은 이 문서가 기준입니다.

## 1. 목적과 범위

`build-static-site.ps1`은 로컬 파일을 읽어 GitHub Pages에 올릴 정적 파일을 생성하는 스크립트입니다.

- 서버, 데이터베이스, 패키지 설치, 사용자 정의 GitHub Actions, Git 훅에 의존하지 않습니다.
- 파일을 읽고 정적 HTML·목록·사이트맵을 생성합니다.
- Git add, commit, push 또는 배포를 실행하지 않습니다. 사용자가 생성 결과를 검토하고 직접 커밋·푸시합니다.
- 파일 형식이 계약을 지키지 않거나 생성 결과가 불완전할 가능성이 있으면 이유와 수정 방향을 표시하고 중단합니다.

실행 명령:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ./scripts/build-static-site.ps1
```

프로젝트 루트에서 실행합니다. `-SiteRoot` 매개변수는 별도 복사본이나 격리된 콘텐츠를 처리할 때만 사용합니다.

`-Check`는 모든 입력을 읽고 메모리에서 렌더링·검증한 후 디스크의 생성 결과와 비교합니다. 파일을 쓰지 않으며, 재생성이 필요하면 변경 대상 경로와 일반 생성 명령을 안내하고 종료 코드 1을 반환합니다. 정상 종료 코드는 0입니다. 실행 진행은 수집·렌더링·검증·저장의 네 단계로 표시하고, 오류에는 실패 단계·원인·스크립트 위치를 포함합니다.

## 2. 입력 계약

### 2.1 일기 파일

| 항목 | 계약 |
|---|---|
| 위치 | `database/` 바로 아래 |
| 파일명 | `YYMMDD.html`, 숫자 6자리와 `.html` |
| 날짜 해석 | `20YY-MM-DD`; 실제 달력에 존재하는 날짜여야 함 |
| 문자 인코딩 | UTF-8 입력; 생성되는 텍스트 파일은 UTF-8 without BOM |
| 초안 | 다른 이름 사용. 예: `draft-261031.html`; 이 파일은 게시하지 않음 |
| 빈 본문 | 게시용 일기로 거부. 내용을 채우거나 초안 이름으로 바꿈 |
| 동일 날짜 | 동일 날짜의 게시 파일은 하나만 둠 |

`database/260101.html`처럼 숫자 날짜 이름을 가진 디렉터리는 파일 대신 폴더를 만든 실수로 보고 거부합니다. 날짜 이름 형식과 맞지 않는 다른 파일은 일기 입력으로 읽지 않습니다.

### 2.2 허용하는 일기 HTML 형태

다음 둘 중 하나를 사용합니다.

1. **본문 조각 또는 일반 텍스트:** `database/YYMMDD.html` 파일 내용 전체를 본문으로 사용합니다.
2. **완성된 HTML 문서:** `<html>`, `<head>`, `<body>`가 각각 정확히 한 쌍 있어야 하며, 본문에는 `.post-content` 영역이 정확히 하나 있어야 합니다. `.post-references`는 최대 하나까지 둡니다.

예시:

```html
<!doctype html>
<html lang="ko">
<head><meta charset="UTF-8"><title>초안</title></head>
<body>
  <div class="post-references">
    <a href="https://example.com">참고 자료</a>
  </div>
  <div class="post-content">
    <p>일기 본문</p>
  </div>
</body>
</html>
```

스크립트는 `.post-content`와 `.post-references`의 안쪽 내용을 읽습니다. 중첩 `<div>`는 깊이를 세어 종료 위치를 찾습니다. 생성 후에도 이 두 영역의 본문은 다음 실행 때 다시 읽을 수 있도록 유지되고, 페이지 틀·메타 정보·canonical·날짜·내비게이션은 재생성합니다.

### 2.3 본문 형식과 줄바꿈

- HTML 태그가 **없는** 본문은 일반 텍스트로 처리합니다. 빈 줄은 새 `<p>` 문단, 한 줄 바꿈은 같은 문단 안의 `<br>`이 됩니다.
- HTML 태그가 **있는** 본문은 직접 작성한 HTML 구조를 사용합니다. 문단은 `<p>`, 같은 문단의 줄바꿈은 `<br>`로 명시합니다.
- 본문 전체에 태그가 하나라도 있으면 나머지 일반 텍스트 줄을 자동으로 문단화하지 않습니다. HTML과 일반 텍스트를 섞기보다 원하는 구조를 HTML로 완성해서 작성합니다.
- 첫 문단이 날짜만 표시하면 파일명 날짜를 기준으로 `YY.MM.DD` 형식으로 정규화합니다.

### 2.4 허용 HTML과 거부 조건

본문과 참고 링크에는 다음 태그를 사용할 수 있습니다.

`a`, `abbr`, `article`, `aside`, `b`, `blockquote`, `br`, `cite`, `code`, `dd`, `del`, `div`, `dl`, `dt`, `em`, `figcaption`, `figure`, `footer`, `h1`–`h6`, `header`, `hr`, `i`, `img`, `kbd`, `li`, `mark`, `ol`, `p`, `pre`, `q`, `rp`, `rt`, `ruby`, `s`, `samp`, `section`, `small`, `span`, `strong`, `sub`, `sup`, `table`, `tbody`, `td`, `th`, `thead`, `time`, `tr`, `u`, `ul`, `var`, `wbr`.

추가 규칙:

- 여는 태그와 닫는 태그는 올바르게 짝을 이룹니다. `<br>`, `<hr>`, `<img>`, `<wbr>`는 닫는 태그가 필요하지 않습니다.
- `<a>`에는 `href`, `<img>`에는 `src`가 필요합니다.
- `<script>`, `<style>`, `<iframe>`, `<object>`, `<embed>`, `<form>`과 문서 틀 태그(`<html>`, `<head>`, `<body>`, `<base>`, `<meta>`, `<link>`)는 본문 안에서 거부합니다.
- `onerror`, `onclick` 등 이벤트 속성, 인라인 `style`, `srcdoc`, `javascript:` URL은 거부합니다.
- 허용 목록 밖의 태그는 자동으로 제거하거나 임의 변환하지 않고 거부합니다. 새 태그가 필요하면 안전성과 생성 결과를 검토한 후 코드의 `Assert-DiaryMarkup` 허용 목록과 이 문서를 함께 수정합니다.
- HTML 태그처럼 보이는 텍스트를 본문에 표시하려면 `<`와 `>`를 `&lt;`, `&gt;`로 작성합니다.

### 2.5 본문 링크 표식

본문에 다음 형식으로 쓰면 링크로 처리합니다.

```text
[[https://example.com/path]]
```

- `http://` 또는 `https://` URL만 허용합니다.
- 표식은 `.post-content` 안의 일반 본문 텍스트에 둡니다. HTML 태그의 속성 안에는 두지 않습니다.
- URL 표식은 본문에서 제거하고 `.post-references` 영역으로 이동합니다. 따라서 본문에서 표식을 쓴 위치가 위쪽이어도 아래쪽이어도 표시 위치는 본문 위 참고 링크 행으로 일정합니다.
- URL만 쓴 표식의 링크 문구는 URL입니다.
- 표시 문구가 필요하면 다음 형식을 사용합니다.

```text
[[링크|https://example.com/path|관련 자료 보기]]
```

- 형식이 깨진 `[[...` 표식은 일반 글자로 남기지 않고 파일명과 올바른 예시를 알려주며 거부합니다.
- HTML `<a href="…">…</a>` 링크도 허용합니다.

### 2.6 사진 파일과 설명

| 항목 | 계약 |
|---|---|
| 위치 | `media/섹터폴더/사진파일` |
| 섹터 폴더 | `media/` 바로 아래 한 단계 |
| 사진 파일 | 섹터 폴더 바로 안에 둠. 더 깊은 사진 폴더는 거부 |
| 섹터 이름 | 영문 대소문자, 숫자, 하이픈만 사용: `[A-Za-z0-9-]+` |
| 지원 확장자 | JPG, JPEG, PNG, WebP, GIF, AVIF, HEIC |
| `media/` 루트의 사진 | 거부. 섹터 폴더로 옮김 |
| 알려진 비지원 이미지 형식 | BMP, SVG, TIFF, ICO, JFIF, APNG 등은 자동 누락시키지 않고 거부 |

`pictures.js`의 `descriptions`는 선택 설명 데이터입니다. 현재 섹터와 같은 이름의 섹터에 실제 파일이 남아 있으면 설명을 보존합니다. 파일 목록은 디스크를 기준으로 다시 만들므로 `files` 배열을 수동으로 편집하지 않습니다. HEIC는 갤러리에서 제공하지만 Google 이미지 사이트맵에서는 제외합니다.

원본의 부모 폴더는 `media/`, HTML 갤러리 폴더는 `pictures/`로 고정합니다. `media/`는 반드시 존재하며 섹터를 최소 하나 유지합니다. 빈 섹터는 허용합니다. 빈 폴더도 섹터 이름 규칙을 지켜야 합니다. 기존 `picture/` 또는 `picutre/`가 남아 있으면 이동 지침과 함께 거부합니다.

## 3. 생성 결과 계약

`build-static-site.ps1`은 입력을 기준으로 다음 결과를 생성하거나 갱신합니다.

| 출력 | 생성 내용 |
|---|---|
| `database.js` | 발견한 `YYMMDD.html` 파일 목록 |
| `pictures.js` | 현재 섹터와 사진 파일 목록, 보존한 설명 |
| `database/YYMMDD.html` | 독립 일기 페이지, 정적 본문, 날짜, 참고 링크, 이전·다음 일기, SEO 메타와 BlogPosting JSON-LD |
| `index.html` | 최근 일기 8개의 초기 정적 본문과 사이트 메타 정보 |
| `archive.html` | 전체 일기의 초기 정적 본문 |
| `pictures.html`, `pictures/섹터.html` | 현재 섹터별 사진 갤러리 |
| `sitemap.xml` | 홈·전체 일기·각 일기·현재 갤러리와 지원되는 이미지 URL |

`index.html`의 기존 `<head>`는 공통 템플릿으로 읽습니다. 완전한 `<head>`, 입력 문자열 자체가 `/`로 끝나는 절대 HTTPS canonical(쿼리·fragment 없음), title, description, robots, Open Graph URL, Twitter title, JSON-LD의 `@graph`가 하나씩 유효해야 합니다. 템플릿이 계약을 어기면 생성물을 쓰지 않고 복구 지침과 함께 중단합니다.

섹터 이름이나 사진 파일이 바뀌어 더 이상 생성되지 않는 갤러리 HTML 파일을 스크립트가 자동 삭제하지 않습니다. 입력 파일을 자동 삭제하지 않는 안전 경계입니다. 예전 섹터 페이지를 제거하려면 오류에 표시된 경로를 확인하고 해당 예전 생성 파일을 직접 삭제한 뒤 재생성·검사하여 커밋합니다.

현재 갤러리 목록에 없는 `pictures/*.html`은 검증 오류로 보고 경로를 표시합니다. 해당 파일이 이전 생성물인지 검토하고 삭제한 뒤 다시 생성합니다.

## 4. 실패 및 파일 안전 계약

스크립트는 발견한 파일을 순서대로 즉시 덮어쓰지 않습니다.

1. 모든 일기·사진·템플릿을 검사합니다.
2. 생성할 파일 내용을 메모리에 구성합니다.
3. `validate-static-site.ps1`로 메모리의 생성 결과를 검사합니다. 일기·사진 manifest와 실제 폴더, 갤러리 상태·사진 수·경로, 사이트맵 전체 페이지·지원 이미지 집합, canonical·공유 URL·구조화 데이터·제목, 로컬 href/src 대상과 경로 대소문자를 확인합니다. 모든 검사가 끝난 다음 같은 파일 경로에 임시 파일과 기존 파일의 백업을 준비합니다.
4. 임시 파일을 출력 경로에 교체합니다.
5. 교체 중 오류가 생기면 기존 파일을 백업에서 복원합니다. 복원도 실패하면 백업 파일 경로를 오류에 표시하고 백업을 보존합니다.

따라서 날짜 오류, HTML 계약 위반, 잘못된 링크 표식, 사진 경로 오류, 잘못된 SEO 템플릿 때문에 일부 페이지만 먼저 갱신되는 일을 막습니다. 디스크 자체의 장애나 권한 문제는 데이터 검증으로 예방할 수 없으며, 복원 오류 시 표시된 백업 파일을 보존해야 합니다.

주요 거부 상황과 수정 방법:

| 거부 이유 | 수정 방법 |
|---|---|
| 잘못된 `YYMMDD.html` 날짜 | 실제 날짜를 파일명에 사용 |
| 전체 HTML 문서에 본문 영역이 없거나 중복됨 | `.post-content` 하나, `.post-references` 최대 하나로 정리 |
| 닫히지 않거나 짝이 맞지 않는 태그 | 오류가 가리키는 태그를 닫거나 잘못된 중첩을 수정 |
| 지원하지 않는 태그·속성·URL scheme | 허용 HTML을 사용하거나, 새 요구사항을 검토해 코드와 계약을 함께 갱신 |
| `[[...]]` 형식이 깨졌거나 태그 속성 안에 있음 | 정확한 링크 표기를 일반 본문 텍스트에 배치 |
| 비지원 이미지·잘못된 섹터 이름·중첩 사진 | 지원 형식으로 변환하고 파일을 섹터 루트로 이동 |
| 홈 canonical·SEO 템플릿·JSON-LD 손상 | 정상 생성된 `index.html`의 공통 `<head>`를 복원 |
| 생성 대상 파일 경로에 폴더가 있음 | 충돌하는 폴더를 이름 변경하거나 이동 |

오류 메시지는 가능한 경우 파일 경로와 기대 형식, 수정 방법을 포함해야 합니다. 코드가 안전하게 처리할 수 없는 입력을 조용히 무시하거나 임의로 정규화해서는 안 됩니다.

`test-seo.ps1 -SiteRoot 경로`는 같은 검증기를 사용해 저장된 결과만 검사합니다. 외부 HTTP(S) 링크의 접속 여부(같은 호스트의 별도 저장소 포함), 이미지 파일의 디코딩, JavaScript 실행 및 화면 배치는 검사 범위 밖입니다. `test-static-site.ps1`은 작은 임시 사이트에서 성공·거부 사례와 실패 시 출력 보존을 검증하고 임시 폴더를 정리합니다.

## 5. 변경 시 지켜야 할 원칙

새 입력 형식이나 생성 기능을 추가할 때 다음 항목을 함께 갱신합니다.

1. 이 계약서의 입력 규칙·변환·실패 조건
2. `scripts/build-static-site.ps1`의 파서·검증·출력
3. `README.md`의 사용자 작성법과 명령 안내
4. `scripts/test-seo.ps1` 또는 격리된 입력으로 성공 사례와 거부 사례

성공 사례만 확인하지 않습니다. 계약 위반 사례가 명확한 오류로 거부되고, 오류가 났을 때 생성 대상 파일이 변경되지 않는지도 확인합니다.
